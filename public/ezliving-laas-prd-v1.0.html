Context

Tim Ziss's Living-as-a-Service (LaaS) vision, first laid out June 4, 2026, spans seven conceptual layers — real estate, furnishings, mobility, services, storage, exchange, and AI/robotics. This document breaks each layer into concrete platform requirements so there's something tangible to work from once Tim decides how he wants to run point on the build (and separately, on the Corcoran distribution relationship, which is being handled on its own track).

01

Real Estate Foundation

What exists: 9201 Fourth Ave (pilot, Bay Ridge) + 2 pipeline properties, 2027–2028 delivery.

Platform Needs

  • Property/unit database — floorplans, pricing, availability, buyer status, closing dates
  • Buyer CRM — lead → contract → close → LaaS onboarding (the handoff point into every other layer)
  • Closing document integration (title, mortgage, HOA/condo docs)
  • Ownership/resident directory — single source of truth every other layer reads from

Resources

  • Data model + backend (property, unit, buyer, resident entities)
  • Bridge/API to whoever underwrites closing + financing
Open Question
Who's the mortgage lender partner? Does each property need its own instance, or one multi-tenant platform serving all three from day one?
02

Furnishings Highest Risk

Vision: Italian designer-curated packages (Option A/B/C), amortized into the 30-year mortgage, move-in ready same week as closing.

Features / Products

  • Package selection tool — buyer picks A/B/C pre-close, sees renders + pricing
  • Vendor/designer relationship management
  • Procurement + install logistics for ~395 units across 3 properties
  • Cost amortization calculator (ties to Layer 1 mortgage integration)
  • Warranty/replacement tracking per item (feeds Cloud Closet's digital twin)

Resources Needed

  • Interior design/vendor partner(s) — Corcoran has asked to meet this team
  • Install/logistics contractor (movers, furniture installers)
  • Financing partner willing to embed furnishings cost into the mortgage
Open Question
Is "financed into mortgage" legally and structurally solved today, or still a concept needing a lender partner and legal framework? This is the single most unusual and unproven assumption in the entire model.
03

Mobility Partial Roadmap

Vision: Autonomous cars (Zipcar-style, embedded), Blue Highway hydrofoils (NYC ↔ Hamptons, Manhattan ↔ Connecticut).

Features / Products

  • Booking/dispatch app for building-embedded vehicles
  • Integration point with Flywheel — natural internal synergy
  • Hydrofoil booking/scheduling (Blue Highway vessel still in development, 2029 target)

Resources Needed

  • Vehicle fleet or leasing partner — autonomous fleets aren't commercially mature; likely need a conventional EV fleet as v1 bridge
  • Blue Highway is years out — treat as roadmap, not v1 requirement
Open Question
Is Flywheel the intended mobility backend for EZLiving? Obvious internal cross-venture integration worth raising directly with Tim.
04

Services v1 Candidate

Vision: DoorDash, Uber Eats, Instacart, dry cleaning, laundry, package management, utilities/WiFi — all bundled.

Features / Products

  • Single resident app/portal — the daily front door across all services
  • Package management — smart lockers or concierge desk + notifications
  • Utilities/WiFi bundling — building-wide account, billed via LaaS subscription
  • Third-party service aggregation (API integration or concierge-request routing)

Resources Needed

  • Building staff/concierge for package handling
  • Vendor agreements/affiliate relationships with delivery services
Open Question
Deep API integration (residents order inside the EZLiving app) vs. lighter concierge-request layer (staff place orders)? Very different build complexity — needs a decision early.
05

Cloud Closet Recommend Partner

Vision: AI-powered physical asset management — digital twin of possessions, smart box assignment, seasonal concierge, resale marketplace. SPS-branded.

Features / Products

  • Digital inventory/twin — photo + catalog every stored item per resident
  • Smart box/pickup logistics (functionally identical to Clutter/MakeSpace)
  • Seasonal rotation concierge
  • Resale/marketplace layer for stored items

Resources Needed

  • Physical warehouse/storage facility, or partnership with an existing operator
  • Pickup/delivery logistics fleet or contracted service
Open Question
Build in-house or partner/license from an existing on-demand storage operator? This is the most operationally complex, capital-intensive layer (real warehouses, real trucks) — strong candidate to partner rather than build.
06

Exchange Phase 2+

Vision: Property swap clearing house (no brokers) as the network scales across properties/cities.

Features / Products

  • Listing/matching engine for residents wanting to swap within the network
  • Valuation/equity-transfer logic — legal + financial infrastructure, not just an app
  • Legal framework for property exchange without traditional brokers

Resources Needed

  • Real estate attorney specializing in property exchange structures
Open Question
Only relevant once there's meaningful multi-property/multi-city scale. Not a v1 requirement — but legal groundwork is slow to stand up, so early scoping is worthwhile.
07

AI + Robotics Experimental

Vision: AI building management + companion robots for elderly residents (Tesla pilot referenced).

Features / Products

  • Building management AI — predictive maintenance, energy, security monitoring
  • Companion robot pilot — far-future, not core to launch

Resources Needed

  • Tesla or similar robotics partner (referenced but not confirmed as active)
Open Question
Confirm whether the "Tesla pilot" is an active conversation or aspirational framing — affects whether it belongs in the near-term roadmap at all.
08

Cross-Cutting Platform Requirements

Infrastructure needed regardless of which layer is being built — the backbone every layer plugs into.

  • Resident-facing app/portal — the unifying front door across Services, Mobility, Cloud Closet, and community/Exchange
  • Admin/ops dashboard — building staff view: packages, requests, maintenance, resident directory
  • Identity & accounts — single resident login across all 3 properties, multi-tenant from day one
  • Billing/subscription engine — LaaS is "one payment" bundling mortgage + furnishings + utilities + mobility + services. This consolidation is a serious fintech build on its own — likely wants a payments partner (Stripe Connect or similar, per existing Flywheel experience) rather than being built from scratch
  • GeoPulse AI integration — already built (neighborhood intelligence engine); should feed the resident app as the "why this neighborhood" layer and the pre-close marketing/sales funnel

Suggested Next Steps

  1. Confirm which layers already have real partners/contracts vs. which are still conceptual — furnishings financing especially, since that's the load-bearing wall of the whole model.
  2. Scope a true v1 MVP — most likely Layers 1 + 2 + 4 (real estate handoff, furnishings, daily services), since Mobility, Cloud Closet, Exchange, and AI are either partner-able or Phase 2+.
  3. Identify the build owner — is this an SPS-built platform, or does Tim have separate product/eng resources already in motion?
  4. Get a real financing partner conversation started for the furnishings-into-mortgage piece — the single riskiest unproven assumption in the entire model.
