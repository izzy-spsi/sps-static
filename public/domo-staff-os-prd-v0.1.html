01
Overview
Executive Summary

Izzy asked for one system where all staff information, scheduling, communication, training, and discipline live — with the explicit goal of optimizing labor spend. This document audits what already exists, proposes additional features, and lays out the architecture and phasing to build it for real.

Design principle: Toast is the source of truth for identity, wage, and clock data. Staff OS is the source of truth for everything Toast doesn't do — scheduling intelligence, training, discipline, messaging, and labor optimization logic.

Key Finding

Three partial systems already exist for this problem, built independently, none connected to each other or to Toast. The strongest foundation (a real Next.js + Prisma app called domo-scheduler) has never been deployed. Recommendation: consolidate onto that foundation rather than starting a fourth codebase.

Requirements
HR Policy Encoding

Standing policy from the 2026-07-03 managers meeting (MEMORY.md) must be enforced by workflow, not just documented:

  • Hire fast / fire fast within 30-day probation window (minimizes unemployment insurance exposure)
  • Zero-tolerance, no probation grace: theft, drugs — already in the signed handbook
  • Izzy personally handles every exit interview, with Jerry present
  • Hard rule: never write up an employee without talking to them directly first — no surprise write-ups
  • Labor target: 30% of net sales in F&B labor (aspirational — currently intentionally overstaffing to build bench)
Enforcement Design

A "Write-Up" action in the system requires a linked "Conversation Logged" step first, timestamped, before the formal warning can be finalized. The system should make rule-breaking harder, not just record that it happened.

Technical
Architecture
  • Frontend: Next.js (App Router) — reuse domo-scheduler's existing app/staff/* and app/manager/* structure
  • Backend/DB: Migrate domo-scheduler's Prisma schema from SQLite → Postgres, deployed (not local)
  • Auth: Existing JWT pattern in lib/auth.ts — PIN login for staff (fast, phone-friendly), password login for managers
  • Toast sync: New scheduled job mirroring the toast-sync.mjs pattern — pulls employee roster + clock-in/out (via the now-confirmed-working Analytics API credential) into Staff + a new TimeClockEvent table
  • Jarvis API layer: Extend the already-scaffolded app/api/jarvis route per the mandatory /api/jarvis/status build standard
